# G1 Data Contract

## ROS2 clocks and messages

`RobotState43` stores named `q/dq/tau_est[43]`, a validity flag for every dimension, and IMU values. `ActionTarget43` stores the candidate target, action sequence, source-state sequence, and compute-start, compute-finish, and send timestamps. `XRHandTargets` stores a monotonic sequence, source timestamp, two wrist poses, and 21x3 keypoints for each hand.

The recorder uses `ActionTarget43.header.stamp` as its reference time. It first resolves robot state by `source_state_sequence`; if that lookup fails, it falls back to nearest-timestamp matching. Each camera independently selects the frame with the smallest absolute time difference. Signed differences are stored in Parquet, and observations outside the configured thresholds are rejected.

Default thresholds are 15 ms for robot state and 40 ms for each camera. Recalibrate these limits from measured device rates and clock synchronization. Do not loosen them only to increase the number of accepted samples.

## Episode directory

```text
data/raw/EPISODE_ID/
  metadata.json
  steps.parquet
  videos/head.mp4
  videos/left_wrist.mp4
  videos/right_wrist.mp4
  raw_mcap/                 raw ROS2 bag
```

Each Parquet row represents one actual action timestamp.

| Field | Shape | Meaning |
|---|---:|---|
| `q`, `dq`, `tau_est` | `[43]` | Full robot values in the canonical joint order |
| `imu` | `[10]` | Quaternion `xyzw`, angular velocity, and linear acceleration |
| `validity_mask`, `imu_valid` | `[43]`, scalar | Availability of the full state and IMU |
| `observation_state` | `[28]` | Current dual-arm and dual-hand state |
| `target_action` | `[28]` | Candidate generated by IK or the policy before the safety gate |
| `action` | `[28]` | Target approved and published by the safety gate; falls back to the candidate when no approved command is matched, while `command_applied=false` |
| `command_applied` | scalar | Whether an approved command with the same action timestamp was matched |
| `action_validity_mask` | `[43]` | Joint dimensions controlled by the command |
| `compute_*_ns`, `sent_ns` | scalars | Teleoperation or policy compute and send timestamps |
| `state_delta_ns` | scalar | State timestamp minus action timestamp |
| camera delta fields | 3 scalars | Camera timestamp minus action timestamp |
| `task`, `subtask` | string | Overall instruction and current phase |

`command_applied=true` records that the safety gate published the command associated with the action timestamp.

## Episode splits and action chunks

Training, validation, and test data must be split by complete episode. The default split excludes failed and unlabeled episodes. At time `t`, the LeRobot loader requests the next 50 actions. Repeat-last padding preserves the tensor shape at an episode tail, while `action_step_mask` marks only real future steps. The 28-dimensional action is padded to 32 dimensions, and the final four entries of `action_dim_mask` are always false.

Flow loss is reduced only over this intersection:

```text
valid future step AND active G1 dimension AND RTC postfix step
```

## Normalization

The `PI05` path uses per-dimension training-split quantiles:

\[
x_{norm}=2\frac{x-q_{01}}{q_{99}-q_{01}+10^{-6}}-1.
\]

Policy output is inverse-normalized with the same statistics and then truncated to the first 28 dimensions. Checkpoint export copies the normalization statistics. Training and deployment must not use different joint orders or statistic files.

`scripts/compute_norm_stats.py` applies `action_step_mask` before computing action statistics, so repeated tail padding is not counted multiple times. Sidecar text and RECAP-style weights do not affect numeric statistics.
