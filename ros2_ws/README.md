# G1 ROS2 Overlay

The workspace contains two ROS2 packages:

- `g1_pi07_interfaces`: `RobotState43`, `ActionTarget43`, and `XRHandTargets` messages.
- `g1_pi07_bringup`: named joint-state adaptation, MoveIt dual-arm IK, Dex3 retargeting, action-centred recording, safety gating, and MCAP launch files.

## Default topics

| Topic | Type | Producer |
|---|---|---|
| `/robot/state43` | `g1_pi07_interfaces/RobotState43` | `state_adapter` |
| `/xr/hand_targets` | `g1_pi07_interfaces/XRHandTargets` | Built-in UDP bridge or a compatible external bridge |
| `/control/action_target43` | `g1_pi07_interfaces/ActionTarget43` | `teleop_action` or the VLA client |
| `/g1/upper_body_position_command` | `sensor_msgs/JointState` | Final safety-gated robot command |
| `/camera/*/image_raw/compressed` | `sensor_msgs/CompressedImage` | Three RGB camera drivers |

## XR UDP/JSON contract

The repository does not depend on a specific Quest, PICO, or Vive SDK. `xr_udp_bridge` accepts one JSON datagram per XR sample. It listens on `127.0.0.1:7001` by default and enforces packet-size, packets-per-tick, monotonic-sequence, and optional source-clock-offset limits.

```json
{
  "sequence": 42,
  "timestamp_ns": 1787880000123456789,
  "left": {
    "valid": true,
    "wrist": {
      "position": [0.31, 0.18, 0.46],
      "quaternion_xyzw": [0.0, 0.0, 0.0, 1.0]
    },
    "keypoints": [[0.0, 0.0, 0.0]]
  },
  "right": {
    "valid": true,
    "wrist": {
      "position": [0.31, -0.18, 0.46],
      "quaternion_xyzw": [0.0, 0.0, 0.0, 1.0]
    },
    "keypoints": [[0.0, 0.0, 0.0]]
  }
}
```

The abbreviated example shows one keypoint. A real message must contain exactly 21 `[x,y,z]` entries for each hand. Ordering follows the common MediaPipe/OpenXR-compatible convention: wrist 0, thumb 1-4, index 5-8, middle 9-12, ring 13-16, and little finger 17-20.

Calibration is configured in `g1_pipeline.yaml`:

```text
p_robot = translation + R(q_xr_to_robot) * position_scale * p_xr
q_robot = q_xr_to_robot * q_xr
```

When XR and ROS2 do not share a clock domain, use the ROS2 receive timestamp. Enable `use_source_timestamp=true` only after measuring and configuring the clock offset.

## Build and launch

```bash
python -m pip install -e .. --no-deps
colcon build --symlink-install
source install/setup.bash
ros2 launch g1_pi07_bringup record_g1_episode.launch.py \
  episode_id:=demo_0001 \
  enable_xr_udp_bridge:=true
```

The MoveIt SRDF must define `left_arm` and `right_arm` planning groups and expose `/compute_ik`. Before recording, verify that incoming `JointState.name` values cover all 43 canonical names in `src/g1_pi07/joints.py`.

## Command safety boundary

`robot_command_adapter` guards command publication with `enable_robot_commands`, confirmed limits, `/low_level/stable=true`, `/safety/estop=false`, message freshness, in-range targets, and a configured per-cycle jump threshold.

The approved `JointState.header.stamp` preserves the original `ActionTarget43.header.stamp`. The recorder uses that exact timestamp to distinguish:

- `target_action`: the candidate generated by IK or the VLA before the safety gate;
- `action`: the command approved and published toward the robot controller;
- `command_applied`: whether the approved command was matched.

“Applied” identifies the command published by the safety gate for the matching action timestamp.

Set the final outcome before stopping recording:

```bash
ros2 param set /episode_recorder success_label true
# Or:
ros2 param set /episode_recorder success_label false
ros2 param set /episode_recorder failure_reason "object slipped"
```

The recorder finalizes Parquet and MP4 files when the launch stops. After an unexpected shutdown, regenerate the episode from `raw_mcap`; do not train on an incomplete episode directory.
